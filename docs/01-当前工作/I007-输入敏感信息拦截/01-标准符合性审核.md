# I007 方案 · DSH 插件标准符合性审核

更新时间：2026-09-13（Asia/Shanghai）
审核对象：`docs/01-当前工作/I007-输入敏感信息拦截/00-方案.md`

## 一、结论

**产品设计与扩展点选择合规；包清单与接线层不达标。** 共 5 项必修：不修会直接违反仓库既有契约断言，或让新包无法按现有链路产出可用产物。

分三层看：

| 层 | 判定 | 说明 |
| --- | --- | --- |
| 行为设计（引擎、拦截管线、安全语义） | ✅ 合规 | 只用官方扩展点，未接管宿主 React 节点；安全约束比标准更严 |
| 包清单（manifest / 产物路径 / 依赖策略） | ❌ 不达标 | `inject` 混入仅类型导入的包；缺 `types`/`exports` 形态；插槽注册缺 `registrant` |
| 接线与发布（构建 / 测试 / 发布链路） | ❌ 不达标 | 方案自相矛盾：§六 说包自带构建，§十一 却写「改根配置」 |

## 四、必修项与改法

### P0-1｜`inject` 去掉 `-ui-slots`

`@deepseek-ai/dsh-client-ui-slots` 只提供类型，属「仅类型导入」。放 `peerDependencies` 正确（根包也如此），但不得出现在 `dsh.client.inject` 里。修正后 inject 只保留：`client-runtime`、`client-locale`、`ui-conversation`、`ui-input-trigger`。

`react` / `react-dom` / `react/jsx-runtime` 属宿主启动器静态模块，必须走 `neverBundle`，既不进 `inject` 也不进 peer 之外的任何声明。

### P0-2｜补齐清单并为 Host 半边产出类型

```json
"main": "lib/index.mjs",
"types": "lib/index.d.mts",
"exports": {
  ".": { "types": "./lib/index.d.mts", "default": "./lib/index.mjs" },
  "./client": { "default": "./lib/client.js" },
  "./package.json": "./package.json"
}
```

配套把 Host 半边构建改成 `dts: true`。原方案的 `dts: false` 会让 `types` 指向不存在的文件。

### P0-3｜插槽注册补 `registrant`

```ts
ctx.slots.register({ name: 'conversation.input.dock', id: 'input-guard', order: -90, locale: NS, registrant: 'michengai-input-guard' }, Dock)
```

### P0-4｜包自包含，推翻「挂根工具链」

§十一 原「接入点清单」建议扩根 `tsconfig.include` / `vitest.include` / `tsdown` 入口，该做法废弃，理由三条：

1. **发布链路断裂**：根 `tsdown` 的 `packageId`、banner id、`deps.neverBundle`、lucide 别名都是为根包定制的；共用后新包无法单独 `pnpm pack` 出可用产物。
2. **断言与门禁错位**：`run-assertions.mjs` 只扫根 `tests/`，新包断言写了也不会执行；而根 `tsc --noEmit` 又会把新包一并纳入，等于用根包的编译假设约束另一个可独立发布的包。
3. **与已发布兄弟包不一致**：`@michengai/dsh-automation` 自带 `scripts`（build/typecheck/test）与自己的 devDependencies，是对外发布的事实标准。

正确做法：新包自带 `tsconfig.json` + 构建入口 + `vitest.config.ts` + `scripts`；根侧只保留一条聚合脚本供 CI 汇总。

### P0-5｜发布链路二选一

必须明确：新包**独立发布**（需单独绑定 npm Trusted Publishing 与 `v*` tag 流程，参照 `docs/00-交接入口/07-开发与构建.md`），还是**只作本机安装、不发布**（则不纳入 CI 发布门禁，但 README 要写明安装路径）。原方案两者都没写。

## 五、方案自身的内部矛盾

| 位置 | 内容 | 冲突 |
| --- | --- | --- |
| §六 包结构 | 列出自带的 `tsconfig.json` / `tsdown.config.ts` | 与 §十一「扩展根 tsconfig/vitest/tsdown」矛盾 |
| §七 第 6 条 | `pnpm --filter ... test` | 要求包自带 test 脚本，即 §六 形态；与 §十一 冲突 |

处理：统一按 §六 执行，§十一 的接入点表已替换为「根侧只加一条聚合脚本」。

## 六、独立编译才会暴露的一个坑（已并入方案 §六）

包内 `tsconfig.json` 独立编译时，`ctx.sessions` / `ctx.workspaces` 的类型增强**不会自动加载**。必须在包内显式引入：

```ts
import type {} from '@deepseek-ai/dsh-api-session-controller/client'
```

并把 `@deepseek-ai/dsh-api-session-controller` 列为包内 devDependency。根包之所以没有这条，是因为它的 `src/client/index.ts` 已在同一编译程序里引入了该增强；一旦把代码挪进自包含的包，这条就会立刻报错。

## 七、行为设计层：合规，无需修改

- **扩展点合规**：只注册 `conversation.input.dock` 隐形扩展，经 `ctx.conversation.input` / `ctx.inputTriggers` / `input.notify` 工作，未搬移或替换宿主 React 节点 → 符合技术架构基线。
- **DOM 级按键捕获可接受**：`keydown` 捕获 + `preventDefault` 不改动宿主节点，根包已有同款先例（`src/client/input-history-keyboard.ts` 处理 `ArrowUp/Down`），方案把它收敛在单一模块，符合「兼容适配集中」的要求。
- **空 `apply()` 有官方先例**：DSH 自带的 `ui-input-trigger` 就是这样。
- **安全语义比标准更严**：打码不自动发送、含 chip 或图片时整体放行、相位非 `plain` 时不介入 —— 不违反任何标准，建议同类插件沿用。

## 八、落地自查清单

1. `main`/`types`/`exports`/`files` 形态与 `client-module-contract` 一致，且实际产出对应文件。
2. `dsh.client.inject` 不含 `-slots`、`-primitives` 与 react 系。
3. `dsh.client.platform: 'web'` 显式声明。
4. `packageManager` 与 `engines.node` 对齐仓库基线。
5. peer 用统一范围、dev 用精确钉版（含 cordis `4.0.2`）。
6. bundle 的 `require()` 集合被断言固定为 `react`/`react-dom`/`react/jsx-runtime`。
7. 插槽注册带 `registrant`。
8. 词库命名空间已 `declare module` 注册。
9. 包自带 `scripts`（build/typecheck/test）与 `tsconfig`/构建入口/vitest 配置。
10. 独立契约断言有明确执行入口（包内 `test`）。
11. LICENSE / NOTICE / 双语 README / CHANGELOG 随 `files` 发布。
12. 发布或「仅本机安装」的路径已写明。
