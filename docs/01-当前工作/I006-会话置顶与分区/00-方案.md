# I006 会话置顶与侧栏分区 · 方案

更新时间：2026-09-11（Asia/Shanghai）
状态：待评审（决策点见第八节）

## 一、目标（按图）

设计稿把侧栏树重新定义成「三段信息架构 + 统一会话菜单」：

| 区域 | 承载对象（图注） | 行内菜单 |
| --- | --- | --- |
| 置顶 | 非项目聊天 | 取消置顶 / 重命名 / 归档聊天 / 删除聊天 |
| 项目 | 项目目录 → 项目目录下聊天 | 项目目录下聊天：置顶 / 重命名 / 归档聊天 / 删除聊天 |
| 最近 | 最近聊天 | 置顶 / 重命名 / 归档聊天 / 删除聊天 |
| 设置 | 保持原有开源内容不变 | 不调整 |

由此得出四条需求：

1. **会话置顶回归**：置顶区改为承载「被置顶的会话」，图中的样例是一条非项目聊天。
2. **项目区保持层级**：项目目录下继续渲染其会话，会话菜单与最近区一致。
3. **菜单收敛为 4 项**：置顶/取消置顶、重命名、归档聊天、删除聊天（图中共 4 个图标位）。
4. **文案由「会话」改「聊天」**，且设置页零改动。

## 二、现状基线与差距

| 设计项 | 现状 | 差距 |
| --- | --- | --- |
| 置顶区承载对象 | 仅项目：`pinnedGroups.map(workspace => renderGroup(workspace, 'pinned'))`（`src/client/CodexWorkspaceBrowser.tsx:864-866`），空态文案「拖动项目到此处置顶」（`src/client/locales.ts:118`） | 需改为承载会话 |
| 最近区 | 仅渲染未归属项目的会话 `recentIds`（`CodexWorkspaceBrowser.tsx:525`） | 需排除已置顶会话 |
| 会话菜单 | `sessionMenuItems` 共 10 项：重命名 / 标记未读 / 归档 / 在新会话中继续 / 在资源管理器中打开 / 项目(移动) / 复制 ID / 复制标题 / 复制工作目录 / 删除（`src/client/session-tree.tsx:36-62`） | **完全没有置顶项**；项数与图不符 |
| 文案 | `sessions.rename`「重命名会话」、`sessions.archive`「归档会话」、`sessions.delete`「删除会话」 | 需改为「重命名 / 归档聊天 / 删除聊天」 |
| 门禁断言 | 硬性禁止会话置顶：`tests/session-tree.assert.ts:20,29,63`、`tests/settings-integration.assert.ts:198,250` | 必须同步反转，否则实现与断言互相矛盾 |
| 历史决策 | `CHANGELOG.zh-CN.md` 0.2.102：「移除会话置顶，仅保留项目置顶作为统一的置顶模型」 | 本方案是对该决策的反转，需在 CHANGELOG 与交接文档中显式说明 |

结论：这不是「加一个菜单项」，而是**置顶模型 + 分区职责 + 共用菜单 + 文档断言**四处同时调整。

## 三、数据与持久化设计

### 3.1 事实源

项目置顶当前的事实源是 Host Profile 偏好文件（`src/workspace-preferences.ts`，写入 `~/.dsh/profiles/web/.dsh-codex-ui-preferences.json`），浏览器 localStorage 只做首帧恢复与迁移兜底。**会话置顶复用同一份文件**，不新开第二套事实源。

### 3.2 文件格式

```ts
type WorkspacePreferences = {
  version: 3                 // 2 → 3
  pinnedWorkspaceIds: string[]
  pinnedSessionIds: string[] // 新增
  workspaceGroups: WorkspaceGroup[]
}
```

- 读取：v1 / v2 / v3 均兼容（v1、v2 视为 `pinnedSessionIds: []`）。
- 旧客户端（只认 v2）读到 v3 会判为无效格式，写入时也会丢掉新字段。这是**已知双向兼容缺口**，处理策略见第七节。

### 3.3 失效清理（必须复用现有竞态保护）

沿用 `prunePinnedWorkspaceIds` 的「双基线就绪后才清理」模式，新增 `prunePinnedSessionIds`：

- 仅在 `baselinesReady`（`workspaces.items` 与 `sessions` 都就绪）后清理；
- 清理结果不得在首帧把用户置顶写成空数组（`CodexWorkspaceBrowser.tsx:426-438` 已有同类修复，新逻辑必须沿用同一道闸）。

### 3.4 排序

图未体现置顶内部顺序，提供两个候选（决策点 5）：

- **A**：置顶时间倒序（实现最简，纯派生，无额外持久化）。
- **B**：用户拖拽自定义顺序（复用 `insertPinnedWorkspace(ids, id, beforeId)` 同款插入语义，改动量更大）。

## 四、界面与交互方案

### 4.1 置顶区

- 渲染置顶会话列表，复用 `SessionRow`（含悬停卡片、右键菜单、未读蓝点、运行态、待处理交互）。
- 空态文案待定（决策点 1/2）。
- 会话被置顶后，从项目区与最近区去重，避免同一条会话出现两次。

### 4.2 项目区

- 项目目录 → 项目目录下聊天的层级、分组折叠、拖拽排序、胶囊间距**全部保持不变**。
- 项目内会话行的菜单与最近区完全一致（共用 `sessionMenuItems` 的收益）。

### 4.3 最近区

- `recentIds` 再过滤掉 `pinnedSessionIds`。

### 4.4 会话菜单（三棵树统一改动）

`sessionMenuItems` 增加 `pinned` 选项，输出 4 项：

| 顺序 | id | 文案键 | 图标 |
| --- | --- | --- | --- |
| 1 | `pin` / `unpin` | `sessions.pin` / `sessions.unpin` | `PinIcon()`（Lucide 16px / 1.5px） |
| 2 | `rename` | `sessions.rename` | `IconEditOutline16` |
| 3 | `archive` | `sessions.archive` | `IconArchiveOutline20` |
| 4 | `delete` | `sessions.delete` | `IconTrashOutline16`（danger） |

- 一处改动即同时作用于任务树、频道（`ChannelBrowser.tsx`）、定时（`ScheduleBrowser.tsx`），不需要三处复刻。
- 被移除的项（标记未读 / 在新会话中继续 / 移动到项目 / 复制三项）需确认（决策点 3）；未读蓝点、运行态等**状态展示**不受影响。

### 4.5 文案

- 新增：`sessions.pin`「置顶聊天」、`sessions.unpin`「取消置顶」、`workspace.pinnedEmpty` 若改为会话语义需重写。
- 修改：`sessions.rename` →「重命名」、`sessions.archive` →「归档聊天」、`sessions.delete` →「删除聊天」。
- 中英词典必须同步，CJK 残留与死键断言（`tests/locales.assert.ts`）会拦住漏改。

### 4.6 设置区

按图注**零改动**：不新增设置项、不调整设置页结构。

## 六、验证与门禁

1. `pnpm test` 全量：typecheck → vitest → tsdown → 33 个断言脚本 → 8 个 Chromium 布局脚本（需先 `pnpm exec playwright install chromium`）。
2. 新增测试：
   - 会话置顶读写往返与 Host hydration（含「旧 Host / 未就绪基线」两条分支）；
   - 置顶区渲染会话、最近区去重；
   - 菜单项与图钉图标契约断言。
3. 真实 DSH 页面验收：三段分区、4 项菜单、刷新后置顶保留、删除/归档后置顶清理、卸载后恢复默认侧栏。

## 七、风险与回滚

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 与既有「移除会话置顶」决策相反 | 文档与断言若不同步反转，会出现实现与门禁互相矛盾 | 第 5 节第 7–11 项必须同一批次提交 |
| 偏好文件版本升级 | 旧客户端读 v3 判为无效、写回丢字段 | 优先同批升级；或先保持 v2 + 可选字段并让旧客户端忽略未知字段（需 Host 侧放宽校验） |
| 基线未就绪误清理 | 用户置顶被永久抹掉（历史 P1 事故同款） | 复用「双基线就绪后才清理」闸门，并补回归测试 |
| 三棵树行为漂移 | 频道/定时菜单与任务树不一致 | 坚持共用 `sessionMenuItems`，禁止各树自行拼菜单 |

回滚：卸载插件即恢复 DSH 默认侧栏；Host 偏好文件可降级读取，不阻塞侧栏启动。

## 八、待确认（决策点）

1. **置顶区是否同时保留「项目置顶」？** 图中置顶区只有一条会话。
   - 推荐：置顶区只承载会话置顶，项目置顶从 UI 移除（保留数据兼容读取），模型才真正「统一」。
2. **已置顶会话在项目区/最近区是否仍显示？** 若显示，是否加图钉标记并让菜单首项显示「取消置顶」？
   - 推荐：项目区/最近区不重复渲染，只在置顶区出现，菜单首项按 `pinned` 切换文案。
3. **菜单是否确认精简为 4 项？** 「标记未读 / 在新会话中继续 / 移动到项目 / 复制 ID·标题·工作目录」四项能力是否下线？
   - 若保留，建议放进第二段分隔线，让首屏仍是图上的 4 项。
4. **文案是否统一「会话」→「聊天」？** 涉及历史文档与既有断言中的用词。
5. **置顶内部排序**：置顶时间倒序（简单）还是拖拽自定义（灵活）？
6. **事实源**：Host Profile（推荐，与项目置顶同源）还是仅浏览器本地？

## 九、实施顺序

- **P0 数据层**：偏好文件 v3 + Host 路由 + 客户端读写与竞态闸门。
- **P1 菜单层**：`sessionMenuItems` 4 项 + 文案键。
- **P2 渲染层**：置顶区承载会话、最近区去重、（可选）置顶拖拽。
- **P3 文案层**：中英词典与 README。
- **P4 门禁层**：反转/新增断言，`pnpm test` 全绿。

P0 → P1 可并行前提：先锁定决策点 6；P2 依赖 P0；P4 依赖 P1–P3。
